## 2장 인덱스 기본

### 인덱스 구조 및 탐색
인덱스는 정렬 되어있는 또 하나의 테이블이다.
B*Tree로 되어있는 것이 특징이며, B는 Balanced 약자이며, 루트 부터 모든 리프 블록 까지의 높이는 같다. 즉, 루트-> 리프 블록 까지의 읽는 블록 수 는 같다는 말이다.
또한, 인덱스는 소량의 데이터를 탐색할 때 유용하다. 인덱스 스캔의 비효율을 줄이고, 스캔 후 테이블 레코드로 액세스 할 때 최소화가 필요하다.(== 랜덤 I/O를 줄여야한다.)

인덱스는 수직적 탐색과 수평적 탐색이 이뤄진다.
수직적 탐색은 인덱스를 탐색하기 전 시작점을 찾는 과정이며, 루트에서 브랜치들을 거쳐 리프 블록의 시작점을 찾는다. 쿼리에서는 = 의 등호 표시로 표현된다.
수평적 탐색은 수직적 탐색으로 시작한 시작지점을 기준으로 끝 지점까지 리프 블록들을 탐색하며 ROWID를 얻는다. ROWID는 테이블 레코드에 접근할 수 있는 정보들이 담겨있다.
ROWID는 데이터 블록 주소(Data Block Address)와 로우 번호로 구성되어있어 테이블 레코드를 찾아갈 수 있다.(세그먼트 -> 익스텐트 -> 데이터 블락 -> Row Slot)

### 인덱스 기본 사용법
인덱스는 시작지점과 끝지점이 있어야 Index Range Scan이 가능하다.
따라서, 아래의 경우는 시작지점을 알지 못하여 인덱스 스캔이 불가능하다.

1. 인덱스 컬럼을 가공하는 경우
2. LIKE '%TEST%' 와 같이 중간값을 검색하여 시작 점을 모르는 경우
3. 조건 절에 OR 조건인 경우 (use_concat 힌트를 사용하면 OR Excpansion을 유도해 인덱스 범위 스캔을 가능하게 할 수 있다.)
4. IN절인 경우 (내부적으로 옵티마이저가 IN-List Iterator 방식을 사용해 인덱스 범위 스캔을 가능하게 한다.)

Index Range Scan을 하기 위해서 인덱스 선두 컬럼이 가공되지 않은 상태로 조건절에 있어야 한다.
하지만, 이렇게 인덱스를 탄다고 해서 문제가 없는 것은 아니며, 인덱스 리프 블록에서 스캔하는 양을 따져봐야 알 수 있다.

인덱스를 이용한 소트 연산 생략도 가능하다.

엄격하게 타입 체크를 하는 DBMS도 있지만, 오라클은 형변환을 자동으로 지원해준다.
이로 인해 인덱스 컬럼을 나도 모르게 가공할 수 있다.
일반적으로 숫자형과 문자형이 만나면 숫자형이 이긴다. 즉, 숫자형 컬럼 기준으로 문자형 컬럼을 숫자형으로 변환한다는 뜻이다.
하지만, LIKE는 문자형 기준으로 숫자형 컬럼이 변환된다. LIKE자체가 문자열 비교 연산자 이기 때문이다.
