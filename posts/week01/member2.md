## SQL 실행 순서
- SQL의 실행 순서는 FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY 순으로 실행이 된다.
- SQL은 구문 해석 순서를 파싱 -> 최적화 -> 실행가능한 rowdata 생성으로 이뤄지며, 쿼리를 재사용할 수 있게 라이브러리 캐시에 저장해둔다.
- 실행하기 전에 캐시에서 찾아 있는지 확인하며, 캐싱이 되어있다면 소프트 파싱이 되고 그게 아니면 하드 파싱 즉, 위에서 말한 구문 해석 순서를 다시 해야하는 무거운 연산을 다시 해야한다.

## 옵티마이저 힌트 기술 주의사항
- 주석 /* */에서 +를 붙여 힌트를 사용해야한다.
- 여러개의 힌트를 사용할 때는 ,를 사용하지말아야 한다.
- 테이블에 앨리아스가 있다면 힌트에 그 앨리아스를 사용해야한다.

## 하드 파싱 I/O or CPU
###### 하드 파싱이 I/O 작업인지, CPU 작업인지 묻는 질문으로 이해했습니다. 
- 하드파싱은 CPU 작업이다. SQL의 문법, 의미 검사, 비용 기반 최적화, 실행계획 생성 등을 수행하는 CPU 작업 이기 때문이다.

## 바인드 변수 부작용
- 최초 바인드 값에 유리한 실행계획이 생성되어 이후 다른 값에 불리하게 적용될 수 있다.
