# P102 부서 0~89번 급여 합계

> 1장 · 1.3.4 시퀀셜 액세스 vs. 랜덤 액세스 · 1.3.6 Single Block I/O vs. Multiblock I/O · 1.3.7 Table Full Scan vs. Index Range Scan

부서 번호가 90 미만(`deptno < 90`)인 사원 수(`cnt`)와 급여 합계(`total_sal`)를 조회하세요.

- 사용 테이블: `study.employees` (사원 10만 건, 3,200블록)
  - `employees_pk`: empno — 사번 순서로 적재되어 사번 범위는 블록이 모여 있어요
  - `employees_dept_ix`: deptno — 부서는 사번을 100으로 나눈 나머지라 테이블 전체에 흩어져 있어요

비효율 쿼리는 인덱스를 쓰는데도 블록을 9만 개 넘게 읽어요. 테이블은 3,200블록뿐인데 말이죠.
**인덱스가 항상 빠를까요?**

## 스키마

```sql
-- 1장 데이터셋: 사원 10만 건. 행마다 메모(200바이트)가 있어 테이블이 인덱스보다 훨씬 크다.
-- empno 순서로 적재되어 empno 범위는 블록이 모여 있고, deptno(= empno mod 100)는 테이블 전체에 흩어져 있다.
CREATE TABLE employees (
  empno   NUMBER        NOT NULL,
  deptno  NUMBER        NOT NULL,
  ename   VARCHAR2(20)  NOT NULL,
  sal     NUMBER(7, 2),
  memo    VARCHAR2(200),
  CONSTRAINT employees_pk PRIMARY KEY (empno)
)
/
CREATE INDEX employees_dept_ix ON employees (deptno)
/
```

목표: Buffers ≤ 4,000
